# Deep-Dive Guide: `application.properties`

> **Purpose**: This guide breaks down every single configuration line in [`application.properties`](../src/main/resources/application.properties), explaining **what it is doing**, **why it is required**, **behind-the-scenes mechanics**, and **how interviewers test this knowledge**.

---

## 1. Application & Server Settings

```properties
spring.application.name=order-management
server.port=8080
```

### What It Does:
* `spring.application.name`: Sets the logical name of this microservice/application. Used by logging frameworks, Spring Cloud / service registries (Eureka/Consul), and tracing tools (Zipkin/Micrometer).
* `server.port`: Specifies the port on which the embedded Tomcat server listens (default is `8080`).

---

## 2. MySQL Database Connection

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/order_management?createDatabaseIfNotExist=true&useSSL=false&serverTimezone=UTC&allowPublicKeyRetrieval=true
spring.datasource.username=root
spring.datasource.password=root
spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
```

### Breakdown of the JDBC URL Parameters:
| URL Parameter | What It Does & Why We Need It |
|:---|:---|
| `createDatabaseIfNotExist=true` | If the schema `order_management` does not exist on your MySQL server yet, MySQL will automatically create it on startup. Prevents `Unknown database 'order_management'` errors. |
| `useSSL=false` | Disables TLS/SSL handshake requirements for local development to avoid certificate verification errors. (In production, set to `true`). |
| `serverTimezone=UTC` | Explicitly forces UTC timezone. Prevents date/time skew between your Java JVM (which defaults to local time) and MySQL storage. |
| `allowPublicKeyRetrieval=true` | Needed for MySQL 8+ authentication (which uses `caching_sha2_password`). It allows the client to retrieve the server's public key during connection handshake. |

## 3. HikariCP Connection Pool Settings

```properties
spring.datasource.hikari.maximum-pool-size=10
spring.datasource.hikari.minimum-idle=5
spring.datasource.hikari.idle-timeout=300000
spring.datasource.hikari.connection-timeout=20000
spring.datasource.hikari.max-lifetime=1200000
```

### Why Do We Need a Connection Pool?
Opening a new TCP connection and authenticating with MySQL on every single HTTP request costs **30–60ms** of latency. **HikariCP** (Spring Boot's default high-performance connection pool) keeps a pre-warmed pool of active connections ready to be borrowed.

```
Incoming Request ──► Borrow Connection from Pool (~0.1ms) ──► Execute Query ──► Return to Pool
```

### Parameter Explanations:
* `maximum-pool-size=10`: The maximum number of simultaneous DB connections Hikari will keep. For most medium services, 10–20 connections can serve thousands of requests per second because queries execute in 1–5ms.
* `minimum-idle=5`: The minimum number of idle connections Hikari maintains in reserve.
* `idle-timeout=300000` (5 minutes in ms): How long an idle connection can sit before being closed (as long as pool stays above `minimum-idle`).
* `connection-timeout=20000` (20 seconds in ms): Maximum time a request thread will wait for a connection from the pool before throwing `SQLException: Connection is not available`.
* `max-lifetime=1200000` (20 minutes in ms): Maximum lifespan of a connection in the pool before Hikari gracefully retires and replaces it. This must be shorter than MySQL's `wait_timeout` (default 8 hours) to prevent stale/broken connections.

## 4. JPA & Hibernate Configuration

```properties
spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
spring.jpa.properties.hibernate.highlight_sql=true
spring.jpa.open-in-view=false
```

### Parameter Explanations:

#### 1. `spring.jpa.hibernate.ddl-auto=update`
Controls how Hibernate handles database schema generation based on your Java `@Entity` classes:
* `create`: Drops existing tables and creates new ones on startup (❌ **Data loss risk**).
* `create-drop`: Creates tables on startup, drops them on shutdown.
* `update`: Alters tables to add new columns or create new tables if missing. Does **not** delete columns (✅ **Best for local dev**).
* `validate`: Verifies that entities match the DB without making changes. Fails startup if mismatch (✅ **Production standard**).
* `none`: Disables DDL generation completely (used when using Flyway/Liquibase migration scripts).

#### 2. `spring.jpa.show-sql=true` & `format_sql=true`
* Logs the actual SQL queries generated by Hibernate to your console.
* `format_sql=true` pretty-prints the SQL with indentation instead of printing it on one long unreadable line.
* `highlight_sql=true` adds ANSI color coding in terminal logs.

#### 3. `spring.jpa.open-in-view=false` (Crucial Best Practice)
* **What is OSIV?**: Open-Session-In-View keeps the database session/connection open during the entire HTTP request lifecycle—even while rendering JSON in the controller.
* **Why disable it?**: When OSIV is `true` (Spring Boot's default), your application holds onto database connections much longer than needed, leading to connection pool exhaustion under high traffic. It also masks the **N+1 query problem**.
* Setting it to `false` ensures the DB connection is released immediately after the `@Service` method completes.

---

## 5. Interview Cheat Sheet

> **Question 1: What is the difference between `ddl-auto=update` and `ddl-auto=validate`?**
> * **Answer**: "`update` modifies the database schema automatically when entities change, which is convenient during local development. In production, we always use `validate` (or `none`) combined with database migration tools like Flyway or Liquibase to ensure predictable, version-controlled schema migrations."

> **Question 2: Why do you set `spring.jpa.open-in-view=false`?**
> * **Answer**: "OSIV holds database connections open across the entire web request, which can quickly exhaust the connection pool. Disabling it enforces clean boundaries where all database interactions finish in the service layer, and prevents unexpected lazy-loading queries during JSON serialization."
